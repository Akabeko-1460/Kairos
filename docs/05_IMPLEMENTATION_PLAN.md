## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **バックグラウンドタブで音が途切れる** | 中核要件が崩れる | **Phase 0-3 で先に検証**。Web Worker ティッカー + 2秒先読み |
| **メモリ超過でタブがクラッシュ** | 使い物にならない | Phase 0-4 で実測してから素材長を決める。ループ32秒以下、Texture はモノラル |
| ループの継ぎ目が目立つ | 体験が根本から崩れる | Phase 0-2 で検証。等パワークロスフェード、テイクローテーション |
| Safari の Web Audio 実装差 | 一部環境で鳴らない | Phase 3-12 で検証。`setValueCurveAtTime` は特に挙動差が出やすい |
| AI生成素材が「音楽的すぎて」集中を妨げる | Focus が機能しない | プロンプトで melody / percussion / vocals を明示的に排除。長時間の実聴で評価 |
| 素材やIRの商用利用条件が後から問題になる | 公開できない | Phase 2-12 で必ず記録。不明なものは使わない |
| 初回ロードが遅い | 離脱 | 音源を遅延ロード。最初のフェーズ分だけ先に読む |
| Endel の意匠・商標に近づきすぎる | 法的リスク | 独自の名称・配色・UI。Endel の音源や画像を一切使わない |

## 進め方の推奨

1. Phase 0 のスパイク（0-2, 0-3, 0-4）を**最優先**で、他は後回しにしてでも先に終わらせる
2. Phase 1 完了時点で一度**自分で1日使ってみる**。ここでUIの不満を洗い出す
3. Phase 2 の音作りには、コーディングと同じくらいの時間を「聴く」ことに使う
4. 各 Phase の終わりでタグを切り、動くビルドを残す
